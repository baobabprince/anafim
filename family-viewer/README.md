# ענפים — family-viewer

**גרסה 2.0.1** · מציג GEDCOM בעברית ובאנגלית, עם אפשרות לכספת ענן מוצפנת. לצפייה מקומית אין צורך בחשבון או בהגדרת ענן. משפחת ההדגמה בדויה. לתיאור המוצר ראו גם את [README הראשי](../README.md).

## שימוש מקומי

1. פתחו את האתר, או הריצו את גרסת הפיתוח כמתואר בהמשך. אפשר גם להשתמש ב־`anafim.html` לצפייה מקומית.
2. בחרו **פתיחת קובץ GEDCOM** ופתחו קובץ `.ged` או `.gedcom` (עד 30MB). קובצי GEDCOM 5.5, 5.5.1 ו־7 נתמכים בליבה.
3. השאירו זיהוי קידוד אוטומטי. אם השמות משובשים, בחרו קידוד ידנית. UTF-8, UTF-16, Windows-1255 ו־ANSEL הם בין הקידודים הנתמכים.
4. חפשו אדם או לחצו על קרוב כדי למקד את התצוגה. אפשר להחליף בין עברית לאנגלית ולמצוא מסלול קשר בין אנשים.
5. קובץ שמסמנים לשמירה מקומית נשמר בדפדפן **ללא הצפנה**; במכשיר משותף עדיף לא לבחור בכך.

תמונות אפשר לבחור יחד עם ה־GEDCOM או להוסיף לאדם במבט המשפחתי. השיוך לתמונות מקושרות מתבצע לפי שם קובץ; התמונות נשמרות מקומית בלבד אם בוחרים לשמור אותן.

### תרשים להדפסה

במבט המשפחתי בחרו אדם ולחצו על **תרשים להדפסה**. אפשר לבחור תרשים אבות ואימהות עם 3–6 דורות אחורה וענפים צדדיים, או תרשים צאצאים עם 2–6 דורות (האדם הנבחר הוא הדור הראשון, ילדיו בשני ונכדיו בשלישי). בתרשים הצאצאים מוצגים גם בני הזוג המתועדים של כל צאצא, כולל בדור האחרון, אך לא צאצאים של בני הזוג מקשרים אחרים אלא אם הם מופיעים בעצמם בתרשים. אפשר לצפות בתוצאה, להוריד SVG או להדפיס / לשמור כ־PDF ב־A4, A3 או A2 לרוחב; ודאו שגם בהגדרות המדפסת או ה־PDF נבחר אותו גודל דף. כל אדם מופיע פעם אחת; מין מתועד מסומן באמצעות פינות חדות לזכר, פינות עגולות לנקבה ומסגרת מקווקוות לאחר או לא צוין, ללא ניחוש לפי שם או תפקיד. נקודה מסמנת משפחה וחץ מצביע על ילד. קו זוגיות מקווקו ותווית ליד הנקודה מסמנים גירושין (אירוע DIV) או התאלמנות שתועדו במפורש ברשומת המשפחה (למשל אירוע EVEN מסוג widowhood או סטטוס _STAT); פטירה לבדה אינה מספיקה לקביעת התאלמנות. חציית קווים ללא נקודה אינה קשר. מסגרת בקו מקווקו מאגדת ילדים של אותה משפחה. בתרשים האבות והאימהות, בענפים אחרים נבחרת משפחת הלידה או המשפחה הראשונה. מוצגים גם אחים החולקים הורה ממשפחת ההורים הנבחרת, כולל אחים למחצה כשמתועדים. בתרשים צאצאים קבוצות של שלושה ילדים או יותר מאותה משפחה, ללא זוגיות או קשרים נוספים בתרשים, מוצגות אוטומטית במעגל בקצה הענף שלהן, גם אם ענפים אחרים ממשיכים לדורות נוספים. בתרשים אבות ואימהות אפשר לבחור תצוגה מעגלית קומפקטית לילדי ענפים צדדיים; היא לא תמיד מקטינה את התרשים. בתרשים צאצאים בעל מבנה עץ, המעגלים ממוקמים לצד אחיהם והענפים מנותבים בנפרד. בקשרים מורכבים שאינם מאפשרים זאת בלי לשכפל אנשים או להסתיר קשרים, תופיע הודעה שהפריסה הכללית עשויה לכלול חציות. ילדים עם קשרים נוספים בתרשים או עם קשר אימוץ מסומן מוצגים בנפרד. קבוצות גדולות מחולקות למעגלים המחוברים לאותה משפחה. אפשר להציג גם מקומות לידה ופטירה מתועדים; תיבות ארוכות גדלות והשורות נעטפות ללא עיוות האותיות. ה־SVG וקטורי ומכיל גופן Heebo מוטמע לעברית ולטינית ורישיון שימוש (שפות אחרות עשויות להסתמך על גופנים חלופיים; תמיכה בהטמעה תלויה בתוכנה הפותחת). תופיע אזהרה כאשר הטקסט צפוי להיות קטן מדי בהדפסה על דף יחיד. לתרשים גדול כדאי לבחור דף גדול יותר או לצמצם דורות וענפים; הגדלת התצוגה בלבד אינה משנה את גודל ההדפסה. קובץ הייצוא מכיל מידע משפחתי ויש לשמור עליו בהתאם.

## פיתוח ובדיקות

נדרש Node.js 22. מתוך תיקיית `family-viewer`:

```bash
npm ci
npm run dev      # http://localhost:5173/anafim/
npm test         # כל בדיקות היחידה
npm run build    # פלט ב-dist/
```

בדיקות דפדפן דורשות התקנת דפדפני Playwright ושרת פיתוח פועל; בחלון נוסף הריצו `npm run test:e2e`. `npm run standalone` בונה מחדש את `../anafim.html` ומיועד לתצוגה מקומית. קובץ `file://` אינו סביבת ענן/OAuth מתאימה; לענן נדרש דפדפן בהקשר מאובטח של HTTPS או localhost. בקובץ העצמאי חלקים מסוימים של האפליקציה עשויים לדרוש משאבים נוספים; אל תניחו שבדיקת בנייה מחליפה בדיקה ידנית של הפונקציות הדרושות לכם.

## הגדרת ענן אופציונלית למפעיל

השירות משתמש ב־Supabase Auth עם Google, במסד PostgreSQL וב־Storage פרטי. ה־GEDCOM ושם הקובץ מוצפנים בדפדפן לפני העלאה; Google מזהה את המשתמש ואינו מקור מפתח ההצפנה. פריסת אתר ללא הגדרת ענן נשארת זמינה לצפייה מקומית. אין להסיק ממדריך זה שפרויקט ענן מסוים כבר הוגדר או נבדק.

### 1. אתר ופרויקט Supabase

- בחרו כתובת HTTPS קבועה ואת נתיב היישום המלא, למשל `https://example.com/anafim/`. בפיתוח מקומי אפשר להשתמש ב־`http://localhost:5173/anafim/`. דומיין ה־Passkey קשור לכתובת האתר; מעבר דומיין עלול לדרוש שחזור ורישום מחדש.
- צרו פרויקט Supabase והפעילו ב־**SQL Editor** את כל [סקריפט המיגרציה](supabase/migrations/202610180001_private_vault.sql) כגורם מורשה. הוא יוצר את `anafim_vault_heads`, `anafim_vault_versions`, ה־bucket הפרטי `anafim-vaults`, מדיניות **RLS** ו־RPCs לפרסום ולמחיקה.
- ודאו ב־Supabase שה־bucket פרטי, שה־RLS והמדיניות נוצרו, ובדקו הרשאות בפועל עם שני חשבונות נפרדים. אל תסירו את מדיניות ה־Storage המגבילה שנועדה להגן גם מפני מדיניות רחבה אחרת בפרויקט.
- העתיקו את Project URL ואת מפתח ה־**publishable** או `anon` הציבורי בלבד. לעולם אל תכניסו לדפדפן, לקוד או למשתני `VITE_` מפתח `service_role`, מפתח `sb_secret_`, Google Client Secret או סיסמת משתמש.

### 2. Google OAuth והפניות

1. ב־Google Cloud הגדירו פרויקט, מסך הסכמה ו־OAuth Client מסוג **Web application**. אם האפליקציה במצב Testing, הוסיפו משתמשי בדיקה מורשים.
2. ב־**Authorized JavaScript origins** הוסיפו את מקור האתר בלבד, למשל `https://example.com` (בלי הנתיב); לפיתוח, `http://localhost:5173`.
3. ב־**Authorized redirect URIs** הוסיפו את כתובת ה־callback המדויקת המוצגת בהגדרות ספק Google ב־Supabase, בדרך כלל `https://PROJECT.supabase.co/auth/v1/callback`.
4. ב־Supabase → Authentication → Providers → Google הפעילו את הספק והזינו את ה־Client ID וה־Client Secret **בלוח Supabase בלבד**.
5. ב־Supabase → Authentication → URL Configuration הגדירו Site URL והוסיפו ל־**Redirect URLs** את כתובת היישום המלאה, כולל הנתיב והלוכסן לפי הצורך, למשל `https://example.com/anafim/` וכתובת הפיתוח. היישום מבקש חזרה ל־`location.origin + location.pathname`. הימנעו מ־wildcard רחב בייצור.
6. היישום מבקש `openid email profile`, ללא הרשאות Google Drive או אנשי קשר. בדקו התחברות אמיתית, חזרה לאתר והתנתקות בדפדפן מלא; iframe מוגבל עלול לחסום את התהליך.

### 3. חיבור הגדרות ציבוריות לאתר

לבנייה מקומית העתיקו `.env.example` ל־`.env.local` והכניסו **רק ערכים ציבוריים**:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR-PUBLIC-PUBLISHABLE-OR-ANON-KEY
```

הריצו `npm run build` אחרי השינוי והעלו את תוכן `dist/` לאתר ה־HTTPS. הערכים מוטמעים בחבילת הלקוח, גם אם הוזנו כ־GitHub Actions secrets — הם **אינם סודיים**. בפריסת GitHub Actions של המאגר מוגדרים שני secrets באותם שמות; בהיעדרם הבנייה עדיין אפשרית אך הענן לא יוגדר דרכם.

לחלופין אפשר להגדיר את שני הערכים הציבוריים ב־`index.html` של אתר בנוי, לפני `div#root`:

```html
<script id="anafim-cloud-config" type="application/json">
{"url":"https://YOUR-PROJECT.supabase.co","key":"YOUR-PUBLIC-KEY"}
</script>
```

אפשר גם להגדיר אותם במסך החשבון בדפדפן מסוים. סדר העדיפות להגדרות תקינות הוא: משתני build, בלוק `anafim-cloud-config`, ואז ההגדרה המקומית. הבנייה והממשק דוחים מפתח שרת במקום המפתח הציבורי. ה־`base` ב־`vite.config.js` הוא `/anafim/`; התאימו אותו ואת נתיבי ה־OAuth אם מארחים בנתיב אחר.

### 4. שימוש בכספת, שחזור ופרסום אטומי

בממשק הנוכחי מתחברים עם Google, יוצרים כספת עם **סיסמת כספת נפרדת** של לפחות 8 תווים ושומרים את מפתח השחזור; נדרש אישור שמירתו לפני יצירת הגיבוי. בחרו סיסמה חזקה וייחודית. ניתן להוסיף **Passkey** כשהכספת פתוחה, אם הדפדפן ומנהל המפתחות תומכים בהרחבת WebAuthn PRF. כספת קיימת התומכת ב־Passkey ניתנת לפתיחה באמצעותו; אפשר גם להשתמש במפתח השחזור. אל תשלחו את סיסמת הכספת או מפתח השחזור לתמיכה או למפעיל.

אם אבדו כל אמצעי הפתיחה ומפתח השחזור, Google או מפעיל השירות אינם יכולים לשחזר את מפתח הפענוח. המפתח נשמר בזיכרון בזמן שהכספת פתוחה; יש נעילה אוטומטית לאחר יומיים ללא פעילות. זכירת קובץ מקומי נפרדת מהכספת ואינה מוצפנת.

בסנכרון מועלה אובייקט מוצפן חדש, ולאחר מכן RPC מבצע **פרסום אטומי** של הגרסה רק אם הגרסה הקודמת תואמת. במקרה של התנגשות נדרשת בחירת משתמש, ללא דריסה שקטה. עשר הגרסאות האחרונות מוצגות בממשק, אך גרסאות ישנות אינן נמחקות אוטומטית; יש לתכנן עלויות ושימור. כשל רשת עמום עלול להשאיר אובייקט מוצפן יתום, ואין למחוק אותו לפני בדיקת הפניות הגרסאות. אין שיתוף או מיזוג אוטומטי בין חשבונות.

### 5. פריסה, CSP ופרטיות

`public/_headers` כולל כותרות אבטחה למארחים התומכים בפורמט; במארח אחר הגדירו מקבילות. הבנייה מוסיפה גם מדיניות **CSP** כ־meta ב־`vite.config.js`. אם משתמשים בדומיין Supabase מותאם אישית, יש לעדכן את `connect-src` גם בכותרות וגם במדיניות הבנייה, עבור כתובות HTTPS/WSS הנדרשות. `vite.config.js` ו־`public/_headers` כוללים גם יעדים לפונקציות AI אופציונליות; שימוש בשירות חיצוני בהתאם לבחירת המשתמש עשוי לשלוח אליו מידע. מומלץ לבדוק את מדיניות הפרטיות לפני שימוש בנתונים רגישים.

השרת ומפעיל השירות יכולים לראות מטא־דאטה כגון זהות החשבון, זמני עדכון וגודל מידע מוצפן; ההצפנה אינה מסתירה אותם. קוד זדוני שמוגש באותו origin או מכשיר שנפרץ עלולים לגשת למידע כשהכספת פתוחה. לפני שימוש ציבורי בצעו בדיקת אבטחה עצמאית, בדיקות הרשאות ו־OAuth אמיתיות, בדיקת שחזור ותכנון מגבלות ושימור. פרטים נוספים ב־[מדריך הענן](CLOUD-SETUP.md) וב־[מודל האבטחה](SECURITY.md).

## פתרון תקלות

- **„ענן לא הוגדר”**: בדקו ששני הערכים הציבוריים קיימים ותקינים, שהאתר נבנה מחדש ושהדפדפן משתמש בפריסה המעודכנת. בדקו את סדר העדיפות לעיל.
- **Google מחזיר שגיאת redirect או אינו חוזר לאתר**: השוו בין מקור האתר, callback של Supabase וכתובת היישום המלאה ב־Redirect URLs; בדקו מצב Testing ומשתמשי בדיקה.
- **גישה לענן נדחית**: בדקו הרצת המיגרציה, bucket פרטי, RLS, הרשאות משתמש, רשת ו־CSP. אל תפתרו בעיה זו בהוספת מפתח `service_role` לדפדפן.
- **Passkey לא זמין**: בדקו HTTPS / localhost, דומיין תואם ותמיכת PRF בפועל; כספת עם סיסמה או מפתח שחזור ניתן לפתוח גם בלעדיו.
- **סיסמה או מפתח שחזור שגויים**: נסו את הפרטים ששמרתם לחשבון הנכון. אין לעקוף את ההצפנה באמצעות חשבון Google.
- **שמות משובשים**: נסו קידוד אחר במסך הייבוא. מומלץ לייצא GEDCOM ב־UTF-8 אם התוכנה המקורית מאפשרת זאת.
- **התנגשות גרסאות**: בחרו במפורש אם לפתוח את גרסת הענן או לשמור את העותק המקומי מול הגרסה העדכנית; אין מיזוג אוטומטי.

קוד מקור: `src/`; תרגומים: `src/i18n/`; ענן וקריפטוגרפיה: `src/cloud-*.js`, `src/vault-*.js`, `src/CloudAccess.jsx`.
